# Chart order markers and Engine-Held Stop-Limit

Status: implemented. No live-order activity is authorized by this plan.

## Goal

Show working LIMIT orders as yellow full-width dashed 2 px chart lines and STOP_LIMIT triggers as cyan lines, with price-axis chips, per-order drag-to-modify and X-to-cancel. Add an exact modifier+click Chart Order Gesture to STOP_LIMIT Action Templates. During pre/post-market EXTENDED DAY trading, hold STOP_LIMIT orders in eTape until a trusted Last-Eligible Price triggers them, then submit one linked venue LIMIT order. Make custody and every pending/unknown action visible rather than implying broker protection or success.

## Non-goals

- Sending an Engine-Held Stop-Limit to a venue before trigger, or retargeting its venue afterward.
- Inferring a broker-native stop trigger from local price, fill, or generic broker status. Native STOP_LIMIT remains cyan at its trigger until terminal; its marker is cancellable but not draggable. The [trigger-state research](../2026-09-20-stop-limit-trigger-state-research.md) records what future authoritative adapters could add.
- GTC/overnight engine custody, automatic resumption after restart/feed loss, buying-power reservation, a second child row, or a new chart/order execution mode.
- Placing, modifying, or canceling a real order while developing or validating this feature without separate current-session authorization and reconfirmation.

## Current-code evidence

- `engine/internal/exec/core.go` is the single-writer order command path. Submit persists `OrderSubmitted` before an asynchronous broker call. Cancel/replace ACKs currently mean only that asynchronous work launched; adapter errors are logged. That is not sufficient feedback for interactive chart actions.
- `engine/internal/exec/state.go`, `events.go`, `gate.go`, and `types.go` own replay, order status, risk counts, and session rules. `engine/internal/uihub/wsmsg` owns the UI contract; `ui/src/gen/wsmsg.ts` is generated.
- `ui/src/chrome/exec/actionTemplate.ts`, `resolveTemplate.ts`, and `fireTemplate.ts` define/resolve/fire the same saved template for hotkeys and the Deck. `OrderSettingsSection.tsx` edits them; `ui/src/chrome/backup.ts` imports/exports them.
- `ui/src/chrome/panels/ChartPanel.tsx` owns price-coordinate conversion and chart pointer handlers, but does not yet consume `exec.orders`. `ui/src/render/chart/drawings/interaction.ts` already owns drawing gestures. The chart must not route high-frequency ticks through React state.
- A Link Group, not the chart or a global setting, owns symbol and Execution Venue ([ADR 0005](../adr/0005-link-group-owned-execution-venue.md)). The engine's NYSE calendar/DataClose is authoritative; the UI session clock lacks holiday/half-day precision.

## Custody and price rules

| Effective request at submit | Custody |
| --- | --- |
| STOP_LIMIT + DAY + EXTENDED, during premarket or postmarket | Engine-Held Stop-Limit; venue sees no order before trigger. |
| AUTO DAY in premarket/postmarket | Resolve to EXTENDED DAY, then engine-held. |
| RTH, including explicit RTH during pre/postmarket | Broker-native STOP_LIMIT. |
| GTC, IOC, FOK, OVERNIGHT, AUTO overnight/closed, or any other unsupported combination | Broker-native behavior under existing validation; no silent custody fallback. |

The engine supplies a read-only route/deadline preview, and the submit request carries the previewed route expectation. Core re-resolves against its authoritative clock and rejects a boundary race rather than silently changing custody. Premarket parents expire at 09:30 ET; postmarket parents at that trading day's DataClose (normally 20:00 ET, 17:00 ET on an early close). Show the exact deadline and a countdown during the last minute; last-second placement is allowed. A triggered child inherits the parent deadline for its unfilled remainder, even when ordinary venue EXTENDED DAY LIMIT orders would continue into RTH. Broker fill/cancel events settle boundary races authoritatively.

Only new, real-time Last-Eligible Prints may arm or trigger a held parent. BUY/COVER triggers at or above stop; SELL/SHORT at or below. A current trustworthy eligible print already crossing the stop on submit or drag shows “Will trigger now” and triggers immediately after acceptance/release; stale, replayed, gapped, or cached values cannot. Waiting means ticker demand is admitted but no eligible print has arrived since creation/Resume; Armed means one has. Trigger failure is terminal, not an automatic retry. Core performs its full gate both at creation and at trigger; the held parent counts once as open exposure, with its own intent excluded from duplicate trigger checks. No broker order or buying-power reservation exists before trigger, and venue/account checks remain authoritative.

Use the existing execution Core as the custody seam: one stable parent order ID and one account/history row retain STOP_LIMIT identity and `stop → limit` instruction. Persist a stable child client ID before any broker POST; link broker child ID in metadata, never create a second domain row. Durable trigger switches the marker to yellow immediately with `ACTIVATING`; venue acceptance advances to `WORKING`. On restart, adopt a found child; if definitively absent, mark Activation interrupted without reposting; if ambiguous, mark outcome unknown and reconcile/cancel only. A child limit can be modified at its limit price, subject to broker quantity/partial-fill rules. Pretrigger drag changes only stop price; its fixed limit must remain on the correct side of stop.

The template's nonnegative Limit Cushion sets limit = stop + cushion for BUY/COVER and stop - cushion for SELL/SHORT; support dollar or percent input and outward tick rounding. Default is zero. Hotkey/Deck price source and offset still determine stop; chart click determines stop from the snapped chart price. Dollar/cash/buying-power sizing uses the resulting limit; share and position-percent sizing keep current rules. Core validates the final request regardless of UI preview.

## Safety and lifecycle

Pretrigger parents share execution-grade ticker demand per symbol. Admit demand before accepting a parent; reject insufficient subscription capacity. Preserve source, sequence, and gap/overflow provenance in a small execution feed lane rather than deriving triggers from the chart's coalesced bars. On feed/engine or owned-venue loss, pause pretrigger evaluation and warn. A reconnect re-establishes demand but never auto-resumes a parent: manual per-order Resume requires a new real-time print, open deadline, connection, and full gate. Restart begins master-disarmed and pauses all pretrigger parents. No Resume All.

Master Disarm pauses Waiting/Armed. For Activating it persists cancel intent, finds/adopts any child, cancels it, then pauses only if no fill occurred. A Working venue child remains live under ordinary Disarm behavior; Kill Switch targets all nonterminal parents/children. Venue identity is immutable; deletion expires its held parents, never retargets. Venue outage during Activating or Working is an unknown/reconciliation problem, not proof the child is gone.

Live Engine-Held Stop-Limit is disabled per actual broker/environment/account identity until one-time acknowledgement of “Held by eTape — no broker protection” and the primary moomoo OpenD trigger source. Credential/account changes clear acknowledgement. It cannot be disabled while nonterminal parents remain; paper/sim need no acknowledgement. A clean app exit warns with counts, persists pretrigger parents Paused, attempts to cancel Activating/Working children, and requires an explicit danger force-exit if cancellation cannot be confirmed. A crash follows the conservative recovery rules above. The ticket, chart preview, and hotkey/Deck result expose custody; no generic success toast may conceal local custody or ambiguity.

Persist requested/confirmed/failed/unknown cancel and replace actions for venue orders, not merely accepted command ACKs. Permit one pending replace per order; cancel takes priority over a pending replace; block further drag once cancel requested. Reconcile ambiguous outcomes before permitting another price change. A replace rejection restores the previous confirmed price; an unknown outcome retains both previous and requested values. Cancellation remains dimmed `Cancel requested` until venue confirmation, reverts on failure, and stays marked unknown when unresolved. Partial fills remain authoritative: chart drag edits price only, while Core/adapter computes allowable remaining quantity. Terminal status removes the marker; one durable history row keeps fills and reason.

`Cancel Last Order` includes held parents and cancels exactly the newest cancellable trading intention in the current Link Group venue+symbol, ordered by parent creation time then ID. Waiting, Armed, Paused, Activating, Working, and partially filled parents qualify; a cancel-requested intent does not, so a repeated command walks backward. Focused Cancel All uses the same venue+symbol; Account Panel Cancel All uses its venue; Kill Switch is global. Missing venue/symbol is a no-op with feedback. Activating cancellation persists intent and finds/cancels any child without a duplicate submit.

## Chart behavior

- Render only orders for the chart's current Link Group venue and symbol. Pinned charts have no order markers. A permanent venue marker requires broker confirmation; an Engine-Held parent appears only after durable Core acceptance. Pending chart entry has a ghost, not an optimistic working line. Markers do not affect autoscale and have no offscreen-edge surrogate.
- Show yellow LIMIT and cyan pretrigger STOP_LIMIT as full-plot dashed 2 px lines with draggable order label and a price-axis chip containing price and X. The line highlights on hover, but dragging starts only from the label/chip. Native STOP_LIMIT is cyan/non-draggable/cancellable. After a durable held trigger, show only the yellow child limit. Paused cyan is lower-opacity; drag/X do not resume it.
- During drag, show snapped proposed price and highlighted axis chip. Snap to $0.01 at prices ≥ $1 and $0.0001 below $1. On release, immediately request modification. Right-click or Esc during drag restores the confirmed price without a request. Yellow `MODIFYING` plus a faint previous-confirmed line remains until venue confirmation; rejection/unknown states follow the durable action result. X enters `CANCELING`/`Cancel requested`, disables itself, and waits for confirmation. Activating and unknown outcomes use explicit warning styling; X remains available when a recoverable child may exist.
- At an exact shared price, yellow and cyan remain separate line groups offset 1 screen px with stacked chips. Multiple orders in one color group show a count; click opens an order chooser before any per-order drag/cancel, never a group cancel-all. Esc/click-away dismisses it; chart order entry is disabled while it is open.
- Illustrative gesture: Shift+primary-click. Settings accepts an exact one- or two-modifier combination from Ctrl/Alt/Shift, bound to one STOP_LIMIT Action Template only. Import normalization keeps the first duplicate binding and clears/warns on later duplicates; changing a template type clears its chart binding. Hotkey and Deck bindings remain independent ([ADR 0002](../adr/0002-hotkey-deck-layout.md)).
- With the exact modifiers held over the main price pane, show a cyan dashed ghost and axis price, side/quantity, stop→limit, TIF/session, venue, LOCAL/NATIVE custody, deadline, live/paper/sim badge, `Will trigger now`, or a red invalid reason. Hide the horizontal crosshair while retaining the vertical. Live account/position/eligible mark changes recalculate the preview; release submits the exact last shown snapshot and Core validates it again.
- Submit only on primary down/up in the main price pane with <4 px movement, pre-focused window, no modal/editable field/marker/axis/drawing chrome/indicator pane. Existing active chart gestures win; once chart entry owns a valid canvas start, overlapping drawing bindings do not steal it. Esc, right-click, pane leave, focus loss, symbol/venue/template change cancel. Only the hovered chart owns the ghost across multiple charts. One submission per modifier press; release all bound modifiers and press again to rearm. An ignored repeat shows “Release modifier to place another” silently.

## Rollout, rollback, and risks

Ship sim/paper first and soak across premarket, RTH transition, postmarket, early close, feed outage, restart, and venue reconnect. Keep live held custody off per account until acknowledged; do not enable silently through config migration. If the feed lane or recovery cannot distinguish a child outcome, pause/mark unknown and reconcile—never auto-post another child. Roll back by disabling new held admissions while retaining event replay, order visibility, and cancel/reconcile until all existing parents/children are terminal. Main risks are missed/duplicated market prints, clock-boundary races, ambiguous broker POST/replace/cancel outcomes, and confusing local custody with venue protection; the guards and test matrix above are release gates.
